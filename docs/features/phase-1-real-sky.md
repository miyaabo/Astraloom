# Phase 1 — Real Sky

## Status

Done(2026-08-30 Human Check 完了)

前フェーズ: `docs/features/phase-0-starfield.md`(Done)。0次で確立した星の見た目(色・明るさ・サイズ・グロー・瞬き)の表現品質はそのまま引き継ぐ。

## Goal

信頼できる実データを土台に、指定した場所と日時に対応する星空を再現する。

0次は「星がどこにあるか」を仮データで済ませたが、1次では星の位置計算を実データ + 天文計算に置き換える。見た目のレイヤー(shader・config)は変更しない前提で進める(D003)。

正確な天体運動を時間経過とともに再生する機能(Playback)は 2次の対象であり、1次では対象としない。1次のゴールは「ある瞬間の星空を正しく再現できること」。

## Background / Reference

- `PRODUCT.md` — Future Capability Inventory: Real Sky
- `DEVELOPMENT.md` — Phase Roadmap: 1次
- `DECISIONS.md` — D003(見た目と位置計算の分離)、D005(実データ選定は1次で行う)、D007(0次はbackendなし)

## Scope

- 星カタログの正式選定と商用利用条件の確認
- 実星データの前処理・軽量化(0次と同程度、数千〜1万オーダーの見かけ密度)
- 天文座標変換(恒星時計算、赤道座標 → 指定地点の地平座標(alt/az))
- 日時指定(最小 UI)
- 場所指定(最小 UI)
- タイムゾーンの取り扱い(最低限、日時計算が破綻しない範囲)
- 実データを 0次の renderer / shader へ接続(placement 層のみ差し替え)
- 最初の設定 UI(星空画面へのオーバーレイ、D009 の方向性に沿う)

## Out of Scope(1次では作らない)

- 時間を流す再生(再生/停止/速度/巻き戻し)— 2次
- 球面表示・視点移動・ズーム — 2次
- 星座線・星座名・星情報・検索 — 3次
- 天の川・地平線・風景 — 4次
- BGM・環境音 — 4次
- お気に入り・保存・共有・動画出力 — 5次
- アカウント・課金 — 6次/7次
- 本格的なジオコーディング/地名検索 API 連携(最小の場所指定手段があれば足りる)

## Data Requirements

- 星カタログは商用利用条件を確認したうえで選定する(D005)。候補調査と比較は Task 1 で行い、正式採用前に人間へ提案する
- 必要フィールド: 赤経・赤緯・視等級・色情報(色指数またはスペクトル型)
- 0次と同程度の見かけの密度になるよう、等級でフィルタして軽量化する

## Technical Direction

- 星の「位置計算」レイヤーを新設し、0次の「見た目」レイヤーとは責務を分離したまま拡張する(D003)
- 天文計算(恒星時、赤道座標→地平座標変換)を自前実装するか軽量ライブラリを使うかは、Task 3 開始時に調査し提案する
- バックエンドなしで完結させる方向を優先する(D007)。前処理はビルド時、または初回ロード時にクライアント側で行う

## Acceptance Criteria

### Automated / Technical

- typecheck / lint / unit test / production build が成功する
- 既知の明るい星(例: シリウス、ベガ)について、既知の天文データと近い alt/az が算出されることを unit test で確認する
- console error なし

### Human Check

- 指定した場所・日時の星の並びに違和感がない
- 0次で確立した見た目の品質(サイズ感・明暗階層・グロー・色味)が維持されている
- 日時・場所を変えると星の並びが妥当に変化する
- PC・スマホ縦画面で破綻しない

## Questions Claude May Ask

- 星カタログの選定(商用利用条件を含む)
- 天文計算を自前実装するか、ライブラリを使うか
- 場所指定の最初の入力手段(緯度経度直接入力 or 限定都市リスト)

小さな実装詳細では質問せず、合理的に判断して進める。
